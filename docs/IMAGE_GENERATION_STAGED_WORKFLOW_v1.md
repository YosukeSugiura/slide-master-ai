# 画像生成の運用モード — 手動レビュー／自動一気通貫（v1.2）

> 対象：`content_visual_policy_final.md` **v2.5** 第10.4節の実行手順を、独立した画像素材ごとに実施するための運用文書。**PowerPointの作図指示ではない。** 手動レビューモード（第0〜6節）と自動一気通貫モード（第7節）を切り替えて使用する。

**モード選択**：ユーザーが同一のChatGPT通常チャット内で『次』『はい』により一工程ずつ進行したい場合は第8節の**対話型ステップ実行モード**を優先する。画像生成ごとの確認をユーザーが希望する場合は第0〜6節の手動レビューモードを使う。ユーザーがChatGPTだけで画像生成からPPTX納品まで止まらず制作するよう求めた場合は第7節の自動一気通貫モードを使う。第0〜6節の個別承認や新規チャット義務は第7節には適用しない。

## 0. 入力と前提

- 使用可能な制作根拠は、現行の`design_system_general_final.md`、`content_visual_policy_final.md`、対象講義の内容指定、および明示された素材固有プロンプト。過去の会話・生成画像を新規制作の下敷きにしない。
- **分類A**は統合主図画像を1点、**分類B**は比較対象1つにつき独立イラスト画像1点、**分類C**は生成画像を使わず正確な編集可能描画を制作する。
- 画像の生成先は、原則として**PPTX制作担当とは別の新規チャット**とする。ユーザーが画像プロンプトを目視で確認・修正し、実行承認するまで画像生成ツールを呼ばない。
- 無追加API課金での試作を優先するが、使用プランに含まれる機能・制限を超える利用を無料と断定しない。

## 1. 第1段階 — テキストのみで生成プロンプト案を作る

次の文面を、**画像生成しない通常のテキストチャット**へ入力する。素材の内容指定と適用規格を読ませ、画像生成はさせない。

```text
あなたは画像素材の生成プロンプト設計者です。画像はまだ生成しないでください。
提供した現行デザイン規格・視覚表現方針・当該講義内容指定だけを制作入力として、
対象の素材ID［ID］、分類［AまたはB］、題材［題材］について、
後工程でPPTXに画像として挿入する「独立した画像素材1点」の生成指示案を書いてください。
画像生成に渡す完成品宣言と、対象・行動・道具・関係の肯定的な指定を先頭に置き、
視覚表現方針第10.2節の6フィールドをすべて含めてください。
スライド全体、比較枠、タイトル、本文、Takeawayを画像に描かせる命令は除外してください。
出力は (1) そのままコピー可能な画像生成プロンプト本文、
(2) 第10.3節の10項目のPASS/FAILと根拠、
(3) 誤読され得る点だけとしてください。
プロンプトの提案後は作業を停止して、人間の確認・修正・実行承認を待ってください。
```

この時点の全文は**案**である。例示用の文章や検査結果を画像生成用の本文へ混ぜない。

## 2. 第2段階 — 人間による確認・修正・確定

1. ユーザーが全文を読んで修正する。主要チェックは、**独立した画像素材1点という肯定的な完成品定義、描く場面の固有の行為・関係、除外範囲、画風、画像内テキスト禁止、A/B分類の整合**。
2. 修正した全文を再度10.3の10項目で確認する。未解決の条件があれば確定しない。
3. ユーザーが**そのバージョンで画像生成を実行してよい**と承認してはじめて確定する。プロンプト全文と版番号を固定して保存する。**他の作業者や自動処理が黙って全文を短縮・書き換えない**。
4. 複数素材を制作するときは、素材ごとに案・レビュー・承認・版を管理する。個別承認が面倒な場合は、**すべての確定全文を示したうえで一括承認**してもよい。

## 3. 第3段階 — 新規の画像専用チャットで1素材だけ生成

1. PPTX制作・評価・過去の試作内容の文脈を持ち込まず、新規の**画像生成専用チャット**を開く。
2. **ユーザーが確定した画像生成プロンプトの全文だけ**を入力し、独立画像1点を生成する。冒頭の完成品定義・6フィールドを削除しない。余計な「スライドを作って」「全体をデザインして」などの命令を追加しない。
3. UI上のテキスト欄にプロンプトを貼り付けても、内部の画像モデルが受け取る**実効プロンプトの一致は保証されない**。確認できた入力と、観測不能な内部処理を分けて記録する。

この手順を「プロンプト本文をそのままコピーして投入する」試行と呼ぶが、**画像生成モデルへの内部伝達を実測したという意味ではない**。

## 4. 第4段階 — 画像だけを合否判定してからPPTX制作へ進む

- 元の意味契約との一致と、視覚表現方針6.1の5軸を別々に評価する。必須行為の欠落、未指定の事実、スライド全体化、疑似文字、範囲違反は不合格。
- 不合格なら、**観測可能な入力と実際の画像を比較**して原因候補を記録する。プロンプトの改稿案を人間に戻し、再承認後に新たな版として再実行する。採用素材の画像品質・背景透過・解像度を確認する。
- 合格画像だけをPPTX制作担当（Codex CLI等）へ引き渡す。**CLIはPPTXの編集可能テキスト・吹き出し・Takeawayなどの統合と、実レンダリング検証を担当**する。分類A/Bの画像をPPTX図形やSVGプリミティブで代替しない。

## 5. 必要時のImage APIへの移行（自動では実行しない）

- 初回＋プロンプトを調整した1〜2回程度を目安に、**生成範囲違反、意味違反、不要文字**が繰り返されるなら、人手のプロンプト調整だけで改善可能かを再評価する。試行回数は打切り・合格の機械的基準ではない。
- Image APIを使うと、**APIへ送信したプロンプト全文・モデル・サイズ等の設定・生成物をスクリプトで記録できる**。ただし内部処理・モデル追従・ビット単位の再現性まで保証するものではない。
- Image APIは**ChatGPTサブスクリプション／Codex CLIのChatGPTログインとは別のAPI認証・従量課金**。料金・対応モデル・パラメータは実行直前に公式情報を確認する。
- **ユーザーが料金・予算上限・実行対象を確認して明示的に承認するまで**、APIキー作成・課金設定の変更・有料画像生成リクエストを実行しない。無承認の自動フォールバックは禁止。
- 画像の自動生成部分だけをAPI化し、プロンプト案→人間レビュー→確定→単独評価→PPTX統合という段階分離は維持する。

## 6. 素材ごとの監査ログ（最小項目）

| 項目 | 記録内容 |
|---|---|
| source | 規格版・講義内容指定・素材ID・意味契約 |
| draft | 生成プロンプト案、修正履歴、10.3事前ゲート |
| approved | ユーザー承認の有無、確定全文、版番号 |
| execution | 画像専用チャット／API、実際に確認できた投入文字列、未観測の実効プロンプト |
| output | 生成画像、範囲違反の有無、6.1の5軸、採否 |
| integration | PPTXファイル、編集可能要素、実レンダリング、6.2検査 |
| escalation | API移行が必要な理由、費用と利用の明示承認状況 |

**重要：提案・承認・生成・評価を同一段階としてまとめない。** ユーザーが承認した確定プロンプトだけを次段階へ渡す。

## 7. 自動一気通貫モード — 同じChatGPTチャットで完成まで

> このモードは`content_visual_policy_final.md` v2.4 第10.6節に対応する。**ユーザーがChatGPT内での一気通貫制作を求めた場合に適用する。** 本書第0〜6節は従来の「手動レビューモード」の手順であり、このモードへの切替時には毎画像の承認待ち・別チャット移動・Codex CLI引渡しを要求しない。

### 自動実行契約

- **開始時**：ユーザーの一括制作依頼を、通常の画像生成と不合格素材の限定再生成、画像のPPTX挿入、レンダリング検証、完成物納品までの包括承認として受け取る。画像素材の個別プロンプト承認は要求しない。**追加Image API課金、外部購入、講義原文や規格ファイル変更、GitHubコミットは別途明示承認が必要。**
- **入力固定**：許可済みの3つの元資料（デザイン規格、視覚表現方針、講義内容指定）と指定素材だけを根拠にする。実験方式A/B/C（画像先行／PPTX先行／同時依頼）は、図分類A/B/Cと別に記録する。画像対象は必ず個別の独立素材とする。
- **設計と実行**：各素材の意味契約と完成品宣言→6フィールドのプロンプト→10項目事前PASS→画像1点生成→独立評価→不合格なら理由を記録し最大合計3回まで修正・再生成→合格画像のみPPTXへ配置→実レンダリング→採点→納品、を中断せず実施する。PPTX先行なら生成前に骨組みと挿入領域を確定する。
- **評価と監査**：元原文・画像の意味と範囲・背景透過・縦横比・編集可能PPTX要素・指定フォント名・文字溢れ・最終レンダリングを別々に検査する。画像生成ツールの内部実効プロンプトが不明な場合は未確認とする。既存画像流用と今回の新規画像生成実験を混同しない。
- **失敗時**：重大な範囲違反が続く、ツールが使用できない、課金承認が必要、入力資料が矛盾する場合は、検証できた結果と未実施項目を分離して報告する。失敗画像を暫定採用して完了扱いしない。**成功・未達・未実施を明記する**。必要以上の進捗報告により処理を止めない。

### 今後の制作依頼で使う短い指定例

```text
このチャット内で「自動一気通貫モード」を使用してください。
指定した講義内容とデザイン規格を厳守し、画像素材は各1点ずつ独立して生成・検査し、
合格素材を編集可能なPowerPointへ配置してください。
PPTXの実レンダリング、品質評価、修正まで中断せず行い、
完成PPTX、実プレビュー、評価記録をまとめて納品してください。
通常の画像生成の個別承認や別チャットへの移動は不要です。
追加の有料API・外部購入・GitHubへの変更は行わないでください。
```


## 8. 対話型ステップ実行モード（同一ChatGPTチャット・短いコマンド）

> このモードは`content_visual_policy_final.md` v2.5 第10.7節に対応する。**一つのチャットの中で**「次」「はい」により1工程を完了するための方式。第0〜6節の手動レビューの「別の画像チャット」「個別の承認待ち」や第7節の「一度に全工程」を強制しない。

1. `CHATGPT_NEXT.md`を読み、`docs/runs/lecture03_three_slides/STATE.md`の最新current_stepを取得する。
2. 「次」または通常進行の「はい」を受けたら、現在工程だけを**画像生成／PPTX制作／評価／実レンダリングを含めて完遂**し、結果とログをGitHubへ記録する。次工程の自動開始はしない。「状況」は読み取りのみ。
3. 画像生成時には他のスライド全体やA/B/C比較表を生成させず、**1回につき対象素材1点**に限定する。独立素材の検証に失敗すれば不合格にし、回数制限内で再試行する。失敗を切り抜きや既存画像の流用で合格扱いしない。
4. 成功または失敗の記録をGitHubに残し、成果物の実在を確認した上でSTATEを更新する。PNG/PPTXのGitHubへの保存可否は実際の操作で確認する。
5. **別チャットは不要**。同じチャットで続けるのが標準。別チャットへの切替はユーザーが明示的に希望したときだけの任意策であり、工程成功の前提にしない。
6. 追加API課金・外部購入・講義原文の変更・公開権限の変更は自動で行わず、必要なときだけ個別に確認する。

詳細は`docs/workflows/CHATGPT_STEP_CONTROLLER_v1.md`および`docs/workflows/LECTURE03_ABC_AND_3SLIDES_v1.md`を参照。
