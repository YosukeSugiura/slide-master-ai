# STEP3画像素材1点ずつの実行手順 v1.0

> 2026-10-14。入口 `CHATGPT_NEXT.md` → `docs/workflows/NEXT_COMMAND_CONTROLLER_v1.md` → `docs/runs/lecture03_48slides/step3/EXECUTION_STATE.json`。本書は**画像生成の生成物、意味チェック、保存**のルール。生成器に渡す文章ではない。

## 1. 制作対象とP2から引き継ぐ契約

- 全15点（分類Aが4点、分類Bが11点）、スライドS05/S06/S10/S11/S15/S17/S18/S26の画像枠。分類Cは**新規画像を作らない**。画像IDの並び順は `EXECUTION_STATE.json.queue` に固定。
- 参照元の意味契約／x,y,width,height／アスペクト比は `docs/runs/lecture03_48slides/asset_manifest.json`。画像入力の**正本はP3の`step3/prompts/{asset_id}_prompt_vN.txt`のみ**（先頭にファイル名・STEP状態・Markdown見出しがない）。
- **毎回GitHubの原文を読み直し、SHAを検査**。前回の出力画像を手本として安易に転用しない。不合格画像や他スライドを生成入力に混ぜない。
- 原稿本文/Takeaway/表/スライドタイトルはPPTXの**編集可能テキスト**。**学習理解を助ける短い日本語ラベル（工程名・行動名・概念名）は図中に入れてよい**。文字の正確性と縮小可読性を必須QCとする。長文説明・数値・本文を画像に埋め込まない。
- 生成AIの出力を事後にPPTX編集で改ざん・意味修正しない（P3は画像単体のみに責務を限定）。

## 2. 画像生成の実行境界

1. 実行前に`EXECUTION_STATE.json`の `next_asset_id`、`next_prompt_file`、`next_prompt_blob_sha`、`prompt_version`、`max_attempts_for_current_version`を読み、対象ID1点のみについて生成。
2. 生成器に渡す意図は**P3プロンプト本文だけ**。GitHub進捗・チャット履歴・ログ・別素材・完了報告の語句を付加しない。**現在のChatGPT画像生成ツールでは明示promptフィールドがない場合、その送信内容の完全なバイト一致は立証できない**ため、`prompt_transport=CONTEXT_ONLY_UNVERIFIED`と記録。
3. ChatGPT画像生成ツールが`transparent_background`指定を提供する場合は**trueにする**。ツールが透過を宣言していても画像本体のalpha検査は省略しない。
4. 生成結果が予想外のテーマや「STEP完了画像」だったら、内容を読み解かず**即FAIL**。再試行する場合は同じ素材IDのvN指示だけで行い、制限回数の範囲内。
5. モデル呼び出しや保存手段が利用不能なときは`BLOCKED`で停止し、何枚生成したかを偽らない。

## 2026-10-14：ユーザー承認による文字規則の改訂

図の理解を優先し、A/B画像内の短く正確な日本語ラベルを**積極的に許可**する。Aの循環図では「試作」「評価」「改善」「再試作」のように手順を明確にするラベルを優先。Bは狭い枠なので必要な1語程度に限る。**画像に文字があること自体は失格ではない**。ただし読めない小字、誤字、偽文字、不要な説明文、スライドタイトル・Takeawayは不可。過去v2画像の再評価は**生成当時のプロンプト版と現在の評価規則を区別して記録**する。

## 3. 画像単体の検査ゲート（1つでも必須条件にFAILなら不採用）

### G01：対象の一意性
- `asset_id`の契約した行為/役割/構造**だけ**が描かれた1つの独立イラストか。スライド全体・比較ポスター・複数画像のシート・進捗報告になっていないか。

### G02：意味と因果
- 契約した活動/人物/機器が揃うか。たとえばS05は**試作→利用者評価→改善→再試作**。表現のないステップや誤った意味の付け加えはFAIL。
- 矢印があるなら向きと接続先が正確か。曖昧な循環矢印はFAIL。
- S06は使い捨て型と進展型を混同しない。S11は3役割間の上下関係にしない。S26はワイヤーフレーム／モックアップ／操作試作を区別。

### G03：本当の透過と画像形式
- **PNGをバイナリ検査**：PNGシグネチャ、実ピクセルモードRGBA、alphaの透明画素が有意に存在すること（原則全ピクセル中10%以上にalpha=0があること）、不透明の市松模様や白背景の焼き込みがないこと。
- PNGとして返されたというAPI説明やブラウザ上の透過チェッカーだけでは証明にならない。**JPEG/RGBや市松模様入りはFAIL**。背景が不透明しか生成できないモデルでは「PNGで透明」と虚偽記載しない。モデルが透過不可ならBLOCKEDして再設計判断が必要。
- 元画像の改変（背景削除など）が必要なら透明化の処理方法・生成元・品質を別途記録し、勝手な白抜きでPASS扱いしない。

### G04：画風と画角
- インディゴ`#41419E`・ダーク`#30323B`・控えめなアクセント。背景の立体感・3D・強いグラデーション・余計な枠・過剰なキャラクターはFAIL。
- 保存済みの実画素 `width,height` で比率を確認し、P2枠へ等比配置できるか。切れ・極端な余白・文字の潰れを検査。

### G05：視覚評価
- 主役、行為/意味、視線誘導、情報量、造形の統一の各軸を `PASS/FAIL` で記録。小さくしたプレビューで教材として使えるかも確認。
- **短い正確な日本語ラベルは許可**。必須ラベルの誤字・文字化け・工程との不一致・小さすぎる文字、意図しない大学名・素材ID・進捗表示・スライド全体が混入していないか。文字があるという理由だけでFAILにしない。

### G06：ファイルと回復可能性
- `asset_id_prompt_vN_attemptK.png` として**実体**を保存し、画像の`sha256`、RGBA、有効透明率、size、source、保存先（Library file ID/GitHub blob）を付ける。
- FAIL素材は `step3/rejected/` に隔離して履歴に残す。PASS素材だけ `step3/accepted/` の再取得可能な場所に保存。GitHubのテキストログのみでバイナリがあると主張しない。
- 成功・失敗のどちらでも `P3_asset_progress.json` と対象実行ログをGitHub更新。**PASS時は保存先を再一覧または読み戻しで確認してから`EXECUTION_STATE.json`を進める**。

## 4. 失敗とバージョン更新のルール

- vNごとに初回＋最大2再試行、**計3試行**。同じプロンプト版で無限再試行しない。回数の消費は実際に生成器を起動した時のみ。
- v1の不採用画像・失敗・使ったクレジット等の履歴は保持。意味や構図を修正した別版v2は必ず新ファイルを作り、**別版としての初回試行**から数える。失敗を隠すための版更新は禁止（何を変更したかを記録）。
- ユーザーが「ChatGPTが良い」と選択済みのため、Figmaでの再生成・有料外部サービスは**明示の再承認なく行わない**。
- 3回FAIL・保存失敗・生成器に指示を渡せない場合は`BLOCKED`。次の「次」でも状態がBLOCKEDなら勝手に再試行せず、その原因だけ報告。

## 5. 完了の定義

- 各素材PASSは**生成完了ではなく、意味ゲート・本物の透過・画質・保存/ハッシュを全通過した状態**。
- P3全体DONEは15/15素材の実体が再取得可能・QC PASS、重複と欠番なし、`P3_asset_progress.json`と実バイナリ整合、`STATE.md`への移行記録完了のときだけ。
- P3中はPPTXを作成/変更しない。P4で全48ページのフォント/密集本文/S34のチェックディジット不整合を別途検査する。
