# 情報システム論 第3回 — 方式比較と3枚制作のステップ実行計画 v1.0

## 共通条件

- 実行先：**ChatGPT通常チャットのみ**。Codex Cloud/CLI、外部Image APIには自動委任しない。
- 基準リポジトリ：YosukeSugiura/slide-master-ai / minor。STATEを正本とする。
- 学習内容：docs/lecture03_48_selected_3_contents.md の **元48枚版の11・17・35番**。元原稿は保持し、役割説明のPPTX表示文は意味を保つ箇条書き・体言止めへ短文化可。逐語指定のタイトル・Intro・Takeaway・表セルは保持。4:3、白背景、インディゴ #41419E、源真ゴシックP（レンダリングに代替書体なら申告）。
- 視覚分類：slide11=B（3つの独立人物イラスト＋PPTX編集可能比較構造）、slide17=A（統合されたMLOps循環の独立主図1点）、slide35=C（生成画像なし、編集可能表）。
- 方式比較のA/B/Cは制作順序の名前。上記の視覚分類A/B/Cとは異なる。
- ユーザーの「次」一回につきこの表の一行だけ実行。「はい」は通常進行なら「次」と同じ。
- 同一画像の初回＋最大2再試行。新規独立画像を既存画像の再利用で代用しない。画像ツールが比較表やスライド全体を生成したら不合格。
- 出力を検査できない工程は「暫定完了」で先へ進めず BLOCKED とする。

**比較条件の変更**：E02は旧規格で逐語表示した実験結果である。E03以降の短文化規格により、方式間の見栄え比較には文章量の差という交絡が生じる。E07ではこれを明記し、必要なら方式Aも**画像は差し替えず表示文だけ同じ基準で再レンダリング**し、結果を別版で記録する。過去結果の上書きは禁止。

**実験の採点軸**（各1〜5点、合計30点）：画像の独立性、役割の意味的一致、画風と縮小可読性、画像のPPTX挿入適合性、編集可能オブジェクトと原文の保持、レンダリング後の品質。致命的な範囲違反が1つでもある方式は合格にしない。ファイル未作成の軸は未評価とし、採点で水増ししない。

EのBLOCKED時に「次」を押しても勝手に別の方式へ進めない。ユーザーが明示的に「失敗を記録して次の方式へ」と指示した場合、現在の方式を不合格に固定して次へ進める。これにより全方式の結果を取得可能。

## 画像生成プロンプトの基本形式（E/Pの各画像で具体化する）

生成用の「完成品宣言」を最初に置き、描く場面だけを対象にする。例：**「スクラムマスターがチームの作業上の障害を取り除き、メンバーの自己管理と改善を支援する具体的な行動を描いた、背景透過の独立した2Dフラットイラスト画像を1点制作してください。」** 続けて人物の行動・道具・関係・画風・大きさ、文字や疑似文字と全スライド生成の禁止を記述。採点表やPPTXレイアウト一式を画像プロンプトに転用しない。
