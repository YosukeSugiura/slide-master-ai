# P1 v3｜実験・図の再現仕様 D01–D06

このファイルは次の実装工程に渡す「図の意味契約」。P1では結果画像・モデル性能・テストMSEを未生成のまま明記する。生成AIで実験結果やカラーバーを作らない。

## 共通条件
- 入力画像・コード・依存パッケージ版・乱数seed・実行環境・処理パラメータ・出力画像・数値結果を講義ブランチに記録する。
- PPTX本体は4:3。実験図はスライド枠内に余白を確保し、文字・数式・凡例を潰さない。図表の正確なラベル・数値・軸は原則PowerPointで編集可能に保持。
- 同一比較では画像サイズとカラースケールの条件を固定する。色だけで差を伝えず、数値や処理ラベルを併記する。
- PNGはSxxとは別に素材IDを与える。結果の差替えでは条件と値の来歴を保持し、未測定結果を仮値で埋めない。
- 画像引用元やサンプルデータの権利条件と出典を講義資料末尾・ノート等で明記する。
- 画像生成AI利用は分類A/Bの情報理解・具体例に限定し、P1で意味契約、P2で独立画像指示とプレースホルダを確定してから着手する。分類Cのデータ図はプログラム／PPTXで制作。

## D01｜画素・RGB・解像度（S05–S10）
**入力候補：** scikit-image同梱の実RGBサンプルastronaut（取得先と権利表記は実装時に確認）。元画像のshapeとRGB順序を保存する。単一チャネルを係数操作して作った擬似RGBを実RGBの代用にしない。
**処理：**
1. RGBをR/G/B強度画像に分離、同一(x,y)に対応した各値を表示。
2. RGB→グレースケールは採用する変換式（例：skimage.color.rgb2gray）を注記。
3. S05の5×5整数画像は固定の人工入力（0、64、128、192、255）、数字と色を直接対応させる。
4. S09は32×32入力をブロック平均で16×16・8×8に変換し、画素を同サイズの画面領域に最近傍表示。
5. S10は黒8・白8の二つの4×4画像（縦/横二分）を作り、ヒストグラムが同じであることを数値確認。
**出力：** d01_rgb_split.png, d01_pixel_matrix.png, d01_resolution.png, d01_histogram_collision.png, d01_manifest.json。
**検査：** RGB形状と対応座標、画素範囲、縮小方法、ヒストグラム一致。

## D02｜フィルタと特徴マップ（S11–S22）
**入力：** D01と同じ実画像から得るグレースケール、元の0〜1範囲とサイズを固定。
**係数と処理：**
- 平均3×3：全9係数1/9、平均7×7：全49係数1/49。
- Gaussian型近似3×3：(1/16)[[1,2,1],[2,4,2],[1,2,1]]。sum(K)=1を検証。
- Sobel Gx=[[-1,0,1],[-2,0,2],[-1,0,1]]、Gy=[[-1,-2,-1],[0,0,0],[1,2,1]]。
- 数値演算はfloat32またはfloat64を用い、出力を先に0〜255にclipしない。
- 演算を相互相関で統一（例：scipy.ndimage.correlate、mode='reflect'）。S15で数学的畳み込みとの相違を説明。
- 3×3手計算例：各行[0,0,100]、係数各行[-1,0,1]/3、出力100。
**出力：** d02_kernels.png, d02_smoothing.png, d02_sobel_signed.png, d02_feature_maps.png, d02_manifest.json。
**検査：** Kの数値・反転方向・境界処理・Sobel符号・Gx/Gy共通対称表示幅・M非負・全条件の入力一致。

## D03｜手設計特徴と検索（S23–S28）
**入力：** 4×4の二値配列。Q：各行[0,0,1,1]。A：各行[0,1,1,1]。B：全要素0。C：上2行0、下2行1。D：(行+列) mod 2。
**特徴定義：** dx=隣接する右側との差（4×3）、dy=隣接する下側との差（3×4）。f(I)=[mean(abs(dx)),mean(abs(dy))]。これはSobelとは異なる単純な前進差分。
**正解の計算値：**
- f(Q)=f(A)=(1/3,0)、f(B)=(0,0)、f(C)=(0,1/3)、f(D)=(1,1)。
- d(Q,A)=0、d(Q,B)=1/3、d(Q,C)=√2/3、d(Q,D)=√13/3。距離はユークリッド。
- 順位A→B→C→D。AはQと同じ画像ではないため、ランキング例は意図的に特徴の限界も示す。
**出力：** d03_input_grid.png, d03_feature_values.csv, d03_search_distances.png, d03_manifest.json。
**検査：** 配列・特徴値・距離・順位が全一致し、検索性能一般の実測と称さない。

## D04｜ブロック平均Encoderと近似Decoder（S29–S31）
**入力：** 同一の32×32グレースケール画像を0〜1で固定。例えばD01画像から生成し、素材ファイルとして保存する。
**Encoding：** block sizes 2、4、8ごとの非重複ブロック平均。出力16×16、8×8、4×4。
**Decoding：** 保持したブロック平均値をそれぞれ2×2、4×4、8×8へ複製して32×32へ復元。未知の文字位置や画像辞書をDecoderに与えない。
**評価：** absolute error=abs(x-xhat)、MSE=mean((x-xhat)^2)、画素数=1024。全条件で同じ入力・同じグレー表示範囲0〜1。
**数学的確認：** 非重複で入れ子になったブロックについて、ブロック平均は各領域の定数近似の最小二乗解。よってこの構成ではMSE_16≤MSE_8≤MSE_4（数値許容誤差内）。
**出力：** d04_input32.npy, d04_encodings.png, d04_reconstructions.png, d04_abs_differences.png, d04_metrics.csv, d04_manifest.json。
**検査：** 全復元が32×32、平均値と複製値が整合、差分とMSEが一致、再構成画像が元の正解情報を参照していない。

## D05｜CNN（S32–S39）
**入力候補：** sklearn.datasets.load_digits() の8×8手書き数字。値0〜16を/16して0〜1へ。訓練・評価はstratified 80/20 split、random_state=23を候補として固定。
**教育用モデル設計案：** 8×8×1→Conv(1→4,3×3,pad1)→ReLU→MaxPool2d(2)→Conv(4→8,3×3,pad1)→ReLU→Flatten→Linear(128→10)。S37の形状図と一致させる。学習条件（例：Adam、seed=23、30epoch）は実装時に固定し、結果を測定する。
**出力：** 第1畳み込み層の8×8×4応答、第2層の4×4×8応答、同じ未学習テスト数字の入力、学習・テストaccuracy、モデル重み、層名、描画レンジ。
**保存：** d05_model.pt, d05_training.json, d05_input_test.png, d05_features_conv1.png, d05_features_conv2.png, d05_metrics.json。
**検査：** 学習前のランダム値ではなく、実際に最適化した重みで推論。モデル出力形状・入力テストID・各feature channel・モデル学習条件を確認。深層チャネルの恣意的な意味付けをしない。

## D06｜Autoencoder（S40–S47）
**入力候補：** D05と同じsklearn digitsの8×8画像（64次元、0〜1）、同じstratified 80/20 splitを採用すると講義内の一貫性が高い。教師ラベルはAEの学習目標に使用しない。
**モデル案：** 64→32→latent z→32→64、隠れ層ReLU、最後Sigmoid、画素MSE、Adam。z=2、8、32について独立学習。同じepoch、同じtrain/test分割、比較できる学習率と乱数seedを設定。潜在次元でパラメータ数は変わりうることを記録。
**画像比較：** 固定した2〜3枚のheld-outサンプルIDを使用し、同じ画像について入力、z=2/8/32復元、abs differenceを対応表示。全復元は0〜1共通のグレー尺度、差分図も全条件で固定。
**MSE：** 評価集合の全画素平均mean((X_test-Xhat)^2)。最低限MSE、評価件数、seed、学習epoch、optimizer、lr、アーキテクチャ、dataset verをレポート。
**出力：** d06_model_z2.pt, d06_model_z8.pt, d06_model_z32.pt, d06_input_ids.json, d06_reconstruction.png, d06_abs_differences.png, d06_mse.csv, d06_training.json。
**検査：** 訓練に含まれない固定画像で比較、各モデルの再構成を実行。以前の旧デッキのMSEはデータ分割が異なり得るためこの実験の数値として使わない。latent32がいつも最高の性能になると主張しない。
